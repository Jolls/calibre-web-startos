# Calibre-Web on StartOS

> Everything not listed in this document should behave the same as upstream
> Calibre-Web. If a feature, setting, or behavior is not mentioned here,
> the upstream documentation is accurate and fully applicable — see the
> Documentation section of `instructions.md` for links.

[Calibre-Web](https://github.com/janeczku/calibre-web) is a web app for browsing, reading, downloading, and uploading the ebooks in a Calibre library. This package runs it against an empty library of its own, with no Calibre desktop app involved, and can instead keep the library in a NextExplorer folder.

## Image and Container Runtime

The package runs the unmodified `linuxserver/calibre-web` image on `x86_64` and `aarch64`. The image uses its own entrypoint under s6-overlay, so the daemon runs it as PID 1 (`runAsInit`) with `PUID` and `PGID` set to `1000`.

| Subcontainer             | Purpose                                                                                     |
| ------------------------ | ------------------------------------------------------------------------------------------- |
| `calibre-web-sub`        | The Calibre-Web server (`calibre-web` daemon).                                              |
| `set-admin-password-sub` | Runs the `set-admin-password` oneshot as root before the daemon, then exits.                |
| `seed-library`           | A temporary container, created only during a fresh install, that builds the empty library.  |
| `find-libraries`         | A temporary container that lists the Calibre libraries in NextExplorer.                     |
| `import-library`         | A temporary container that runs the `import-library` action's copy, check, and swap.        |
| `set-library-location`   | A temporary container that checks and, if needed, copies a library for the location switch. |

## Volume and Data Layout

Both volumes use embedded SQLite; no database server runs. `/books` is the `books` volume by default, or a folder in NextExplorer's `data` volume once **Set Library Location** has chosen one; the `books` volume is then unused.

| Volume   | Mount point | Contents                                                                                    |
| -------- | ----------- | ------------------------------------------------------------------------------------------- |
| `config` | `/config`   | `app.db` (users, shelves, settings), `store.json`, `gdrive.db`, `.key`, and the app's logs. |
| `books`  | `/books`    | The Calibre library: `metadata.db` plus one folder per author holding the books and covers. |

## File Models

The package models one file, `store.json` on the `config` volume (`startos/fileModels/store.json.ts`). It holds the StartOS-side `adminPassword` and `libraryPath`.

- **`adminPassword`** is generated by the `set-admin-password` action and re-applied to the `admin` user in `app.db` on every start, through Calibre-Web's own `cps.py -s`. A password changed inside Calibre-Web is therefore replaced at the next start.
- **`libraryPath`** is null while the library is on the `books` volume, and otherwise a folder path inside NextExplorer's `data` volume. Only **Set Library Location** writes it, and every start mounts that folder at `/books`.
- **`app.db` settings** are written once, at install: the library path (`/books`), uploads on, and the kepubify path. After that they belong to the user, and nothing re-asserts them.
- **`metadata.db`** is copied once at install from upstream's empty library and is never touched by the package afterwards.

## Dependencies

NextExplorer (`nextexplorer`) is optional, kind `exists`, and required only while `libraryPath` is set: its `data` volume subfolder is mounted read-write at `/books`. The `import-library` and `set-library-location` actions also mount its whole `data` volume at `/import` without declaring the dependency, only while they run. Nextcloud users reach the same folder through Nextcloud's External Storage action.

## Network Access and Interfaces

| Interface | Type | Port | Protocol | Purpose                                                            |
| --------- | ---- | ---- | -------- | ------------------------------------------------------------------ |
| `ui`      | `ui` | 8083 | HTTP     | The Calibre-Web web interface, including its OPDS feed at `/opds`. |

## Installation and First-Run Flow

On a fresh install the package creates the empty library in `/books`, creates `app.db` with the library path and uploads preset, and gives both to uid 1000. There is no first-run configuration screen to complete.

The image's default `admin` login is never reachable: the service cannot start until the `set-admin-password` action has stored a password, and the oneshot applies that password before the daemon starts.

## Actions

**`set-library-location`** is user-facing and hidden while NextExplorer is not installed and the library is on the `books` volume. It chooses between the `books` volume and a NextExplorer folder.

- **When to run it:** to keep the library in NextExplorer, where Nextcloud can show it, or to move it back.
- **What it does with the target:** a folder that holds a Calibre library is adopted as it is; an empty or new folder receives a copy of the library in use; a folder holding other files is refused, as is one whose first path segment is not an existing NextExplorer location. Every check runs on a copy of `metadata.db`: SQLite `integrity_check`, the Calibre tables, and every listed book file present.
- **What it changes:** `libraryPath` in `store.json`; ownership of an adopted or created folder (to uid 1000); and, when the library's identity differs from the one Calibre-Web last used, the book-keyed tables of `app.db`. The previous library is left where it was, so the `books` volume keeps a stale copy after a move to NextExplorer, and a move back uses that stale copy without anything changed in between.
- **Cost:** a full copy for an empty target, using reflinks where the filesystem allows, and nothing for an adopted library. The action only runs while the service is stopped.
- **Repeat safety:** idempotent for the same folder.

**`import-library`** is user-facing. It is hidden while NextExplorer is not installed or the library is stored in NextExplorer. It replaces the whole library on the `books` volume with a Calibre library found in NextExplorer.

- **When to run it:** once, to bring an existing Calibre library onto a new install, or to swap the library for another.
- **What it changes:** the `books` volume, plus the book-keyed tables of `app.db` (shelf contents, read status, bookmarks, download history, Kobo sync state, thumbnails). Users, the shelves themselves, and settings are untouched. Nothing is written to the source.
- **How it stays database-safe:** the source is copied into `/books/.import-staging` and every check runs on that copy: SQLite `integrity_check`, the Calibre tables are present, and every file `metadata.db` lists exists. Only when all pass is the current library deleted and the copy moved into place. A failed check leaves the current library as it was and removes the staging copy. The source is read through a read-only mount, and its `metadata.db` is never opened in place.
- **Cost:** a full copy of the library, using reflinks where the filesystem allows, so disk use briefly includes the source, the staging copy, and the old library. The action only runs while the service is stopped.
- **Repeat safety:** a library that already holds books is replaced only with **Replace the current library** switched on. Running it again with the same source repeats the replacement.
- **Not imported:** another Calibre-Web's `app.db`, so its users and settings do not come across.

**`set-admin-password`** is user-facing; it generates a 32-character password that satisfies Calibre-Web's password policy.

- **When to run it:** at first setup (the task requires it), and whenever the password is lost or should be rotated.
- **What it changes:** `store.json` only. `app.db` is updated at the next start, which is why the action is only allowed while the service is stopped.
- **Cost:** instant; no restart is triggered.
- **Repeat safety:** each run replaces the previous password and the old one stops working at the next start.
- **Outputs:** the username (`admin`) and the new password.

## Tasks

**`set-admin-password`** is raised by init when `store.json` has no `adminPassword`, with severity `critical`, so the service cannot start until it is cleared. Running the `set-admin-password` action clears it. It returns only if `store.json` loses the key, for example after a restore from a backup taken before a password was set.

## Health Checks

The `calibre-web` daemon's `ready` check passes once port 8083 has a listening socket, with a 60-second grace period; Calibre-Web binds the port only after it has finished initializing. A failure after the grace period means the server did not start: read the service logs, where a corrupt or unreadable `metadata.db` or `app.db` shows up as a Python traceback.

## Backups and Restore

The strategy is a wholesale copy of both volumes (`ofVolumes('config', 'books')`); no database is dumped. SQLite files are copied as files. A library stored in NextExplorer is not part of this backup; it is backed up with NextExplorer, and restoring Calibre-Web without it leaves `app.db` pointing at a missing library. A restored instance otherwise needs nothing further: `store.json` returns with the volume and the password is applied at the next start.

## Limitations and Differences

1. Calibre's `ebook-convert` is not installed, so format conversion is unavailable. The image's own mechanism for adding it pulls an extra layer from the internet when the container starts and supports `x86_64` only.
2. Only the `admin` password is managed by the package. If the `admin` user is renamed or deleted inside Calibre-Web, the stored password cannot be applied; the oneshot logs `Could not set the password for 'admin'` and the daemon still starts.
3. The library is meant to have a single writer. Opening the same `metadata.db` from a Calibre desktop install while the server runs is unsupported, and in a NextExplorer folder a desktop sync that replaces `metadata.db` under a running Calibre-Web can lose changes. The package cannot detect or prevent either.
4. The import is a replace, not a merge: two Calibre libraries cannot be combined by copying files, because their book ids collide.
5. A library stored in NextExplorer must be in a folder under one of its locations. The package never writes to Nextcloud's own data directory, whose file cache would not see the changes.
6. Nothing configures outbound email, OAuth, or LDAP; they behave as upstream and need their own settings.

## Quick Reference for AI Consumers

```yaml
package_id: 'calibre-web'
image: linuxserver/calibre-web
architectures: [x86_64, aarch64]
subcontainers:
  [
    calibre-web-sub,
    set-admin-password-sub,
    seed-library,
    find-libraries,
    import-library,
    set-library-location,
  ]
volumes:
  config: /config
  books: /books # or a NextExplorer folder, see libraryPath
file_models:
  - store.json
startos_managed_env_vars:
  - PUID
  - PGID
  - CALIBRE_DBPATH
  - ADMIN_PASSWORD
dependencies:
  - nextexplorer # optional, exists, only while libraryPath is set
interfaces:
  ui: { type: ui, port: 8083 }
actions:
  - set-admin-password
  - set-library-location
  - import-library
tasks:
  - { action: set-admin-password, severity: critical }
health_checks:
  - calibre-web
```
