# Calibre-Web on StartOS

> Everything not listed in this document should behave the same as upstream
> Calibre-Web. If a feature, setting, or behavior is not mentioned here,
> the upstream documentation is accurate and fully applicable — see the
> Documentation section of `instructions.md` for links.

[Calibre-Web](https://github.com/janeczku/calibre-web) is a web app for browsing, reading, downloading, and uploading the ebooks in a Calibre library. This package runs it against an empty library of its own, with no Calibre desktop app involved.

## Image and Container Runtime

The package runs the unmodified `linuxserver/calibre-web` image on `x86_64` and `aarch64`. The image uses its own entrypoint under s6-overlay, so the daemon runs it as PID 1 (`runAsInit`) with `PUID` and `PGID` set to `1000`.

| Subcontainer             | Purpose                                                                                    |
| ------------------------ | ------------------------------------------------------------------------------------------ |
| `calibre-web-sub`        | The Calibre-Web server (`calibre-web` daemon).                                             |
| `set-admin-password-sub` | Runs the `set-admin-password` oneshot as root before the daemon, then exits.               |
| `seed-library`           | A temporary container, created only during a fresh install, that builds the empty library. |

## Volume and Data Layout

Both volumes use embedded SQLite; no database server runs.

| Volume   | Mount point | Contents                                                                                    |
| -------- | ----------- | ------------------------------------------------------------------------------------------- |
| `config` | `/config`   | `app.db` (users, shelves, settings), `store.json`, `gdrive.db`, `.key`, and the app's logs. |
| `books`  | `/books`    | The Calibre library: `metadata.db` plus one folder per author holding the books and covers. |

## File Models

The package models one file, `store.json` on the `config` volume (`startos/fileModels/store.json.ts`). It holds the StartOS-side `adminPassword`.

- **`adminPassword`** is generated by the `set-admin-password` action and re-applied to the `admin` user in `app.db` on every start, through Calibre-Web's own `cps.py -s`. A password changed inside Calibre-Web is therefore replaced at the next start.
- **`app.db` settings** are written once, at install: the library path (`/books`), uploads on, and the kepubify path. After that they belong to the user, and nothing re-asserts them.
- **`metadata.db`** is copied once at install from upstream's empty library and is never touched by the package afterwards.

## Dependencies

None.

## Network Access and Interfaces

| Interface | Type | Port | Protocol | Purpose                                                            |
| --------- | ---- | ---- | -------- | ------------------------------------------------------------------ |
| `ui`      | `ui` | 8083 | HTTP     | The Calibre-Web web interface, including its OPDS feed at `/opds`. |

## Installation and First-Run Flow

On a fresh install the package creates the empty library in `/books`, creates `app.db` with the library path and uploads preset, and gives both to uid 1000. There is no first-run configuration screen to complete.

The image's default `admin` login is never reachable: the service cannot start until the `set-admin-password` action has stored a password, and the oneshot applies that password before the daemon starts.

## Actions

**`set-admin-password`** is user-facing; it generates a 32-character password that satisfies Calibre-Web's password policy.

- **When to run it:** at first setup (the task requires it), and whenever the password is lost or should be rotated.
- **What it changes:** `store.json` only. `app.db` is updated at the next start, which is why the action is only allowed while the service is stopped.
- **Cost:** instant; no restart is triggered.
- **Repeat safety:** each run replaces the previous password and the old one stops working at the next start.
- **Outputs:** the username (`admin`) and the new password.

## Tasks

**`set-admin-password`** is raised by init when `store.json` has no `adminPassword`, with severity `critical`, so the service cannot start until it is cleared. Running the `set-admin-password` action clears it. It returns only if `store.json` loses the key, for example after a restore from a backup taken before a password was set.

## Health Checks

The `calibre-web` daemon's `ready` check passes once port 8083 has a listening socket, with a 60-second grace period; Calibre-Web binds the port only after it has finished initializing. A failure after the grace period means the server did not start: read the service logs, where a corrupt or unreadable `metadata.db` or `app.db` shows up as a Python traceback.

## Backups and Restore

The strategy is a wholesale copy of both volumes (`ofVolumes('config', 'books')`); no database is dumped. SQLite files are copied as files. A restored instance needs nothing further: `store.json` returns with the volume and the password is applied at the next start.

## Limitations and Differences

1. Calibre's `ebook-convert` is not installed, so format conversion is unavailable. The image's own mechanism for adding it pulls an extra layer from the internet when the container starts and supports `x86_64` only.
2. Only the `admin` password is managed by the package. If the `admin` user is renamed or deleted inside Calibre-Web, the stored password cannot be applied; the oneshot logs `Could not set the password for 'admin'` and the daemon still starts.
3. The library is meant to have a single writer. Opening the same `metadata.db` from a Calibre desktop install at the same time as the server is unsupported.
4. Nothing configures outbound email, OAuth, or LDAP; they behave as upstream and need their own settings.

## Quick Reference for AI Consumers

```yaml
package_id: 'calibre-web'
image: linuxserver/calibre-web
architectures: [x86_64, aarch64]
subcontainers: [calibre-web-sub, set-admin-password-sub, seed-library]
volumes:
  config: /config
  books: /books
file_models:
  - store.json
startos_managed_env_vars:
  - PUID
  - PGID
  - CALIBRE_DBPATH
  - ADMIN_PASSWORD
dependencies: none
interfaces:
  ui: { type: ui, port: 8083 }
actions:
  - set-admin-password
tasks:
  - { action: set-admin-password, severity: critical }
health_checks:
  - calibre-web
```
